### API contract

`GET /api/users` query params: `search`, `role`, `status`, `office_id`, `sort` (`name|email|role|created_at`), `direction` (`asc|desc`), `per_page` (1–100), `page`. Response: `data[]` + `meta` (`current_page`, `last_page`, `per_page`, `total`, `from`, `to`).

`POST /api/users` returns the created user + a one-time `temporary_password`. `PATCH /api/users/{id}` updates details. `PATCH /api/users/{id}/status` toggles active. All are guarded by `auth:api` + `role:admin`.

## Summary

The Users screen is now fully server-driven. The backend enforces admin-only access, validates input, supports combined search/filter/sort/pagination, and protects administrators from deactivating themselves or removing their own admin role. The frontend consumes the paginated response and keeps filters in the URL query sent to the API.
