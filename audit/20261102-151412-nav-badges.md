## Summary

- **`GET /api/nav-badges`** returns `{ data: { concerns, missed?, today? } }` scoped by role:
  - **Concerns** — unresolved (`Open` + `Acknowledged`). Office users only see their own office/reports; admin and maintenance see all.
  - **Missed** — `Missed` schedules. Admin = all; maintenance = assigned to them.
  - **Today** — `Scheduled` runs dated today. Maintenance = assigned to them; office = at their office location.
- **Sidebar pills** render only when the count is above 0, with a descriptive `aria-label` (e.g. “6 missed collections”) and a `99+` cap. They appear in both the fixed desktop rail and the mobile sheet for every role.
- **Refresh strategy** — the hook refetches on route change, window focus and the `ecotrack:nav-badges` event; the event is dispatched after concern status changes, schedule status changes and the past-due sweep, so counts stay current without a full reload.

## Notes
- Badges are informational pills, not links, so the 44px touch-target rule does not apply; the parent nav links remain full-size targets.
- The nav-badges request can queue behind slower dashboard queries on `php artisan serve` (single-threaded dev server); in the browser check it appeared within a few seconds.
- Counts are computed on demand — no new tables, migrations or notifications infrastructure.
