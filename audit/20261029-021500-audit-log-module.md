## Summary

Every create/update/activate/deactivate/status-change/delete on the six core models now writes an `audit_logs` row with the acting user, entity, description and changed fields. The `/admin/audit` page lists them newest-first with search and action filters.

## Notes
- Logging is skipped when there is no authenticated user, so seeding does not flood the log; the seeder adds representative entries instead.
- Status toggles are logged as `activated` / `deactivated` (is_active) or `status_changed` (schedule/office status).
- `meta` stores the changed fields for updates.
