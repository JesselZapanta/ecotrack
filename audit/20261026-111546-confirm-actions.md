# Audit: Confirmation modals for actions

**Date**: 2026-10-26 11:15
**Task**: Add a confirmation modal to table actions.

## Files Changed

| File | Changes |
|------|---------|
| `frontend/src/components/ConfirmDialog.tsx` | New reusable dialog — title, description, cancel/confirm, destructive variant, loading spinner, keeps open on API error |
| `frontend/src/admin/user/index.tsx` | Power action now opens a confirmation (“Deactivate/Activate …?”) instead of firing immediately; confirm calls `PATCH /users/{id}/status`; errors keep the dialog open |
| `frontend/src/admin/records/index.tsx` | Delete buttons (desktop + mobile) open “Delete this record?”; confirm removes it and toasts |
| `frontend/src/admin/locations/index.tsx` | Delete opens “Delete this location?” with a linked-records warning |
| `frontend/src/admin/offices/index.tsx` | Delete opens “Delete this office?” with a users/locations warning |

## Behavior

- **Users** — activating or deactivating requires confirmation. Destructive styling for deactivation; the dialog shows a spinner while the API call runs and stays open on failure.
- **Records** — delete asks first; copy notes it will be removed from reports and cannot be undone.
- **Locations** — delete asks first; warns that linked records and schedules may be affected.
- **Offices** — delete asks first; warns that users and locations may be affected.
- Edit actions remain immediate (no confirmation) since they open a form.
- The dialog is keyboard accessible (Radix), closes on overlay/escape when not busy, and uses the shared `Button`/`Dialog` primitives.

## Summary

Destructive and status-changing table actions now go through a reusable `ConfirmDialog` that explains the impact, shows a spinner while the request runs and stays open on failure.
